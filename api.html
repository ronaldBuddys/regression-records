API reference¶

regression-records: record what Python functions do, and replay it later.

Decorate a function with record_func() (or a method with record_method()) and point it at a directory. Nothing is recorded until recording is switched on, with the environment variable REGRESSION_RECORDS=1 or recording(); then each call’s arguments and result are written as a record. Later - after a code change, a library upgrade, on another machine - replay() reruns every recorded call against the current code and reports what changed, with the exact path of each difference:

from regression_records import record_func, replay

@record_func("tests/regression_data")
def score(frame):
    ...

# REGRESSION_RECORDS=1 python run_pipeline.py      records every call
report = replay("tests/regression_data")
assert report.passed, report.summary()

Everything re-exported here is the supported API. Names reachable only through the submodules are internal and may change without notice - with two deliberate exceptions worth knowing about: the record model in regression_records.records (Invocation, SerializedValue, ExceptionRecord) is stable enough to inspect a loaded record with, and regression_records.comparison.paths documents the diff path grammar that ToleranceConfig.path_overrides keys are matched against.

Everything in regression_records.__all__ is importable from the package root; the sections below follow the module that defines each object.

regression_records.decorators¶

The public decorators: record_func() and record_method().

regression_records.decorators.record_func(store, *, record_exceptions=True, tags=None, serializer_registry=None, enabled=True)[source]¶

Record calls to a plain function, when recording is switched on.

Recording is off unless the environment variable REGRESSION_RECORDS is set to 1 (see enable() and recording()); until then the wrapper is a pass-through costing one check. With it on, each call’s normalized arguments and what it returned or raised are written to store as a record, for replay() to check later.

The wrapped function’s observable behavior is unchanged: it receives its original arguments untouched, its return value is passed through, and any exception it raises is re-raised.

Records are never replaced. Recording a call that behaves exactly as an earlier recording writes nothing; recording one that behaves differently adds a record beside the old one, which then fails replay until you delete it.

Parameters:

  • store (RecordStore or str or Path) – Where records are written - a RecordStore, or a path to wrap in one. There is no default location; recording somewhere implicit would be worse than being asked.

  • record_exceptions (bool, default True) – Whether a call that raises is recorded, with the exception in place of a return value. When False it just propagates.

  • tags (Mapping[str, str], optional) – Free-form metadata stored on each record written by this decoration.

  • serializer_registry (SerializerRegistry, optional) – Only used when store is a path; a RecordStore passed in directly carries its own.

  • enabled (bool, default True) – When False the wrapper never records, whatever the environment says.

Returns:

A decorator. The function it returns has an identity attribute: the FunctionIdentity its records are filed under, and replay imports it by.

Return type:

Callable

Raises:

  • TypeError – When the decorator is applied to a generator or async function, or to a staticmethod / classmethod object; or to a function replay could not import again by name - a lambda, a function defined inside another, a functools.partial, or one defined in the script being run (__main__).

  • SerializationError – On a recorded call whose arguments or result cannot be recorded.

  • ValueError – On any call, if REGRESSION_RECORDS holds an unrecognised value.

Examples

>>> import tempfile
>>> from regression_records import record_func, recording
>>> @record_func(tempfile.mkdtemp())
... def double(x):
...     return x * 2
>>> double(4)  # recording is off: a plain call
8
>>> with recording():
...     double(4)  # recorded
8
regression_records.decorators.record_method(store, *, state_attrs=None, exclude_attrs=(), factory=None, record_exceptions=True, tags=None, serializer_registry=None, enabled=True)[source]¶

Record calls to a method, with the object’s state before and after.

Everything record_func() does, plus the receiver: a method’s behavior is as much about the object it acts on as about its arguments, so self is snapshotted before and after the call and both snapshots are recorded. A method that mutates its object is therefore checked on the mutation, not only on what it returned.

self is excluded from the recorded arguments and from the input hash - the state describes the object, and hashing the instance itself would make every instance a separate case. The wrapper is a plain function assigned on the class, so descriptor binding, inheritance, and isinstance are all unaffected.

Parameters:

  • store (RecordStore or str or Path) – Where records are written, as for record_func().

  • state_attrs (Sequence[str], optional) – Attribute names to record, or None (default) for every attribute the instance exposes. A name found in neither snapshot of a call is an error: it selects instance attributes, so a typo or a property would otherwise record nothing.

  • exclude_attrs (Sequence[str], default ()) – Attribute names to leave out - the escape hatch for caches, connections, file handles, back-references to a parent, and anything else that can’t be deep-copied or would differ between runs for uninteresting reasons.

  • factory (Callable[[], object], optional) – Builds a receiver for replay, which then sets the recorded attributes on it. Required with state_attrs or exclude_attrs: a record holding only part of an object’s state cannot rebuild the object on its own. Without either, replay rebuilds the receiver from its full recorded state, bypassing __init__.

  • record_exceptions (bool) – Exactly as in record_func().

  • tags (Mapping[str, str] | None) – Exactly as in record_func().

  • serializer_registry (SerializerRegistry | None) – Exactly as in record_func().

  • enabled (bool) – Exactly as in record_func().

Returns:

A decorator, whose result carries identity as for record_func().

Return type:

Callable

Raises:

  • TypeError – When state_attrs or exclude_attrs is given without factory, or factory is not callable. When applied to a generator or async function, to a method replay could not import (as for record_func()), or above @classmethod / @staticmethod rather than beneath it. A staticmethod has no receiver: use record_func().

  • SerializationError – On a recorded call whose receiver exposes no dict-shaped state, whose state cannot be deep-copied, or for which state_attrs names nothing.

regression_records.replay¶

Replay recorded calls against the current code, and report what changed.

Recording captures what a function did: its arguments, and what it returned or raised. replay() checks, possibly much later and in a different environment, that it still does. For each record in a store it imports the function by its recorded identity, calls the original (undecorated) function on the recorded arguments, and reconciles the result against the recorded one. A method is called on a receiver rebuilt from its recorded state, and its state after the call is reconciled too. Every record is checked on its own; nothing is looked up by input hash, so two records of the same call that disagree simply give one pass and one failure.

Replay only observes. It calls the function beneath the decorator, and while it runs no decorated call anywhere in the process records, whatever REGRESSION_RECORDS says.

regression_records.replay.replay(store, *, tolerance=None, tolerance_overrides=None, select=None, comparator_registry=None, max_diffs=100)[source]¶

Rerun every recorded call in store and reconcile it with its record.

Each record is replayed independently: its function is imported by the recorded identity, the original function beneath the decorator is called on the recorded arguments, and what it returns or raises is compared with what was recorded. Nothing is written to the store, and no decorated call records while replay runs.

A method record is called on a receiver rebuilt in its recorded state before the call - by the method’s factory= when it has one, else from the recorded state alone, bypassing __init__ - and its state after the call is compared as well ($.state_after). The current decorator’s state_attrs, exclude_attrs and factory decide how; state_before is not compared.

Parameters:

  • store (RecordStore or str or Path) – The store to replay. Pass a RecordStore to use a custom serializer registry.

  • tolerance (ToleranceConfig, optional) – Numeric tolerances for every case not matched by tolerance_overrides; the defaults when omitted.

  • tolerance_overrides (Mapping[str, ToleranceConfig], optional) – Tolerances for particular functions, keyed by a glob on "module:qualname" ("pricing.*:price_*"). The first matching pattern wins.

  • select (str or Callable[[RegressionRecord], bool], optional) – Replay only some records: a glob on "module:qualname", or a predicate on the record. A record that cannot be read is matched by a glob against the name its path implies, and is always included under a predicate, so that a corrupt record is never silently skipped.

  • comparator_registry (ComparatorRegistry, optional) – The comparators to use; the default registry when omitted.

  • max_diffs (int, default 100) – The most diffs kept per case; the rest are counted in ReplayCase.diffs_truncated.

Returns:

One ReplayCase per selected record, in record-path order.

Return type:

ReplayReport

Raises:

FileNotFoundError – If store does not exist: a mistyped path would otherwise replay nothing and pass.

Notes

A call is replayed from its recorded inputs alone. A function that reads a clock, a database, an environment variable or other global state sees today’s value, not the recorded one, and its side effects happen again.

Examples

>>> from regression_records import ToleranceConfig, replay
>>> report = replay("tests/records", tolerance=ToleranceConfig(rtol=1e-9))
>>> assert report.passed, report.summary()

regression_records.manifest¶

Run manifests: which records a recording session produced, and under what.

A record says what a call did, but not what code, packages or data it was made with - and since a record’s id is derived from its content, recording identical behavior again writes nothing, so a run that confirmed an earlier recording leaves no trace in the records at all. A session() fills that gap without touching either: every record it sees written ("new") or already on disk ("matched") is listed in a manifest, beside the environment the run had and whatever context the caller supplies (a data version, a seed), written on exit to <root>/_runs/run-<run_id>.json.

Records themselves are unchanged, so manifests can be added to, or deleted from, a store without affecting replay. Replay walks only records/ directories and never reads them.

Paths referenced from a record’s JSON are relative to that record’s own records/ directory, so the whole store (or a single identity directory) can be freely moved or copied as a unit.

regression_records.comparison¶

Structured comparison of a recorded value against a freshly-computed one.

compare() walks both values in lockstep, collecting every difference it finds (it never short-circuits on the first one) into a ComparisonResult. It is a pure function and never raises on a mismatch - turning a failed comparison into a failed case is replay()’s job, which keeps comparison logic independent of recording and replaying.

Containers (dict/list/tuple/set), objects and scalars are walked here: an object is compared attribute by attribute, the same attributes a record stores. Leaf values (numpy arrays, dataframes) are delegated to a Comparator from a ComparatorRegistry, mirroring how serialization dispatches to its serializer registry.

rtol/atol follow numpy.isclose semantics: two values are considered close if abs(actual - expected) <= atol + rtol * abs(expected). They apply once a float is involved: two integers - scalars, arrays or dataframe columns - are always compared exactly.

path_overrides maps a dotted/indexed path prefix (as it appears in path, e.g. "$.output.price") to a different ToleranceConfig to use for that subtree - the most specific (longest) matching prefix wins. An override only changes the fields it was given: the rest are inherited from the config in effect above it.

Variables:

  • rtol (float, default 1e-7) – Relative tolerance, as a fraction of the expected (recorded) value’s magnitude - 0.01 allows 1%. Not symmetric: the actual value does not scale it.

  • atol (float, default 0.0) – Absolute tolerance, in the units of the values compared. With the default of zero, an expected value of exactly 0.0 only matches 0.0.

  • equal_nan (bool, default True) – Whether NaN matches NaN (and NaT matches NaT) at the same position. A NaN or NaT on one side only is always a difference.

  • strict_dtype (bool, default True) – Whether arrays, numpy scalars, Series and dataframe columns must also agree in dtype. When False only their values (and a dataframe’s column names) are compared. Plain Python numbers are unaffected: 1 and 1.0 compare by value either way.

regression_records.serialization¶

Convert arbitrary Python objects to and from a JSON-safe tree.

Leaf values JSON cannot hold (arrays, dataframes, datetimes, …) are handed to a SerializerRegistry, which may offload them to external files. Any other object is stored as its class plus its attributes, by the object path in object_serializer - no serializer is needed for a user’s own class.

The public entry points are to_json_tree() / from_json_tree(), plus register_serializer() for extending the module-level default_registry with support for additional types.

regression_records.serialization.to_json_tree(obj, ctx)[source]¶

Recursively convert obj into a JSON-safe structure.

Only the values JSON represents faithfully - primitives, lists, and string-keyed dicts - are handled here. Leaf values go to ctx.registry (writing external files under ctx.data_dir as needed), and any other object is stored as its class plus its attributes, each converted by these same rules.

Parameters:

  • obj (Any) – The value to convert. A bool, int, float or str subclass (an IntEnum, say) is recorded as its underlying builtin; a numpy scalar keeps its dtype.

  • ctx (SerializationContext) – Supplies the serializer registry and the directory side files go to.

Returns:

None, a bool, int, float or str, or a list / dict of such values. A delegated value becomes a dict tagged with the reserved key "__type__", which from_json_tree() dispatches on.

Return type:

Any

Raises:

SerializationError – If a value is neither a leaf nor rebuildable from its attributes; a dict uses the reserved key "__type__"; a serializer’s payload uses that key; a container holds a reference back to itself; or the serializer chosen refuses the value.

Notes

A NaN or infinite float is tagged ({"__type__": "float", "value": "nan"}) rather than passed through, so the tree is strict JSON (RFC 8259), not just what Python’s json module accepts.

regression_records.serialization.base¶

The extensible serializer protocol and registry.

A Serializer handles one leaf type: a value JSON cannot represent directly and that is not an object to store by its attributes (arrays, dataframes, datetimes, C types from compiled extensions). Serializers are looked up through a SerializerRegistry, so new leaf types can be supported without touching the core tree-walking logic in regression_records.serialization. A user’s own class needs none: anything no serializer claims is stored as its class plus its attributes.
