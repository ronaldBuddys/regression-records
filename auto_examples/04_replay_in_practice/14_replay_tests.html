replay_tests : one pytest test per record¶

replay() returns one report for a whole store. In a test suite you usually want something finer: one test per record, so that a failure names the case that moved and the rest of the store still reports as passing.

replay_tests builds exactly that - a pytest test function, parametrized over the records in a store. This page records a few calls, writes a small test module around replay_tests, runs pytest on it, then breaks a helper and runs it again.

Setup: where records go¶

The code under test reads its store from the REGRESSION_RECORDS_STORE environment variable when it is imported, so the variable is set first (record_func : recording a first call says why).

import os
import tempfile
from pathlib import Path

# In a project: REGRESSION_RECORDS_STORE=tests/regression_data in a .env file, loaded
# with python-dotenv's load_dotenv(). Here: a fresh temporary directory, empty each run.
STORE = Path(tempfile.mkdtemp(prefix="regression-records-"))
os.environ["REGRESSION_RECORDS_STORE"] = str(STORE)
print("store:", STORE)

store: /tmp/regression-records-il95c2rw

Setup: the code under test¶

Replay imports a recorded function by module and name - here, inside pytest - so the code under test lives in a module, scoring, imported from regression_records._examples - support code that ships with the package so that a page can import real code rather than define it in a cell (record_func : recording a first call says more). In your project, this is your own package. Its source, printed below:

score and grade are recorded; weights is the helper beneath score.

import inspect
import re
import subprocess
import sys

from regression_records._examples import scoring

print(inspect.getsource(scoring))

"""Weighted scores and letter grades, for the gallery page ``14_replay_tests``."""

from __future__ import annotations

import os

import numpy as np

from regression_records import record_func

# Where records go is configuration, set by whoever runs this code; never set here.
STORE = os.environ["REGRESSION_RECORDS_STORE"]


def weights(n: int) -> np.ndarray:
    """Return ``n`` linearly increasing weights that sum to one."""
    raw = np.arange(1, n + 1, dtype=float)
    return raw / raw.sum()


@record_func(STORE)
def score(values: list[float]) -> float:
    """Return the weighted average of ``values``, later values weighted more."""
    return float(np.dot(values, weights(len(values))))


@record_func(STORE)
def grade(value: float) -> str:
    """Return a letter grade for a score between 0 and 1."""
    return "A" if value >= 0.8 else "B" if value >= 0.5 else "C"

The test module¶

This is the whole test file:

SUITE = Path(tempfile.mkdtemp(prefix="suite-"))
TEST_FILE = SUITE / "test_regressions.py"
TEST_FILE.write_text(
    "from regression_records import replay_tests\n"
    "\n"
    f"test_regressions = replay_tests({str(STORE)!r})\n"
)
print(TEST_FILE.read_text())

from regression_records import replay_tests

test_regressions = replay_tests('/tmp/regression-records-il95c2rw')

The name must start with test_. pytest collects functions by name, and replay_tests returns an ordinary function; bound to any other name it is silently never run.

In a real project the store path is relative to the repository, as in replay_tests("tests/regression_data"), and the file sits beside your other tests. Keyword arguments are those of replay(): tolerance, tolerance_overrides, select, comparator_registry and max_diffs.

Running it¶

pytest runs in a subprocess here, as it would from a terminal or CI. Being an installed module, scoring is importable there as replay requires, exactly as your own package is importable in your project’s test process.

OUTCOME = re.compile(
    r"::test_regressions\[(?P<case>[^\]]+)\] (?P<outcome>PASSED|FAILED)"
)


def run_pytest() -> tuple[int, dict[str, str]]:
    """Run pytest on the suite, print its output, and return each test's outcome."""
    env = dict(os.environ)
    env.pop("REGRESSION_RECORDS", None)
    result = subprocess.run(
        [sys.executable, "-m", "pytest", "-v", "--no-header", "-p", "no:cacheprovider"],
        cwd=SUITE,
        env=env,
        capture_output=True,
        text=True,
        timeout=120,
    )
    print(result.stdout)
    outcomes = {
        m["case"]: m["outcome"].lower() for m in OUTCOME.finditer(result.stdout)
    }
    return result.returncode, outcomes


code, before = run_pytest()
assert code == 0 and list(before.values()) == ["passed"] * 4

Breaking a helper¶

The test process imports scoring afresh, so a change made in this script would not reach it. A conftest.py that swaps weights for a broken version - equal weights instead of increasing ones - stands in for an edit to scoring.py, and is deleted afterwards.

CONFTEST = SUITE / "conftest.py"
CONFTEST.write_text(
    "import numpy as np\n"
    "from regression_records._examples import scoring\n"
    "\n"
    "scoring.weights = lambda n: np.full(n, 1.0 / n)\n"
)
try:
    code, after = run_pytest()
finally:
    CONFTEST.unlink()

failed = sorted(case for case, outcome in after.items() if outcome == "failed")
assert code == 1 and len(after) == 4
assert [case.split("@")[0] for case in failed] == [
    f"{scoring.__name__}:score",
    f"{scoring.__name__}:score",
]

The two score cases fail, each with its own message: the case’s describe(), naming the function, the record and the value that moved. The grade cases still pass - they replay the recorded scores, so a change upstream of their arguments does not reach them.

What else to know¶

  • A record that cannot be loaded, imported or called fails its test; it is never skipped, so a store cannot quietly stop being checked.

  • A case that passes although the function’s source has changed since recording (replay : exceptions and code drift in the report) passes with a CodeDriftWarning, which a filterwarnings entry can turn into a failure.

  • The store is read when pytest collects the module, and a store path that does not exist is a collection error, not an empty pass.
