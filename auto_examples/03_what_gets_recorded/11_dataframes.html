replay, compare : polars and pandas frames as arguments and results¶

Dataframes are the case that makes recording worth the trouble. Nobody wants to write assertions over a hundred columns by hand, and nobody wants a golden CSV either - it loses dtypes, and it diffs badly.

This page records functions that take and return frames, replays them, and then tours how frames are compared. polars comes first; each section then does the same in pandas and says where the two genuinely differ. It needs both extras, pip install "regression-records[polars,pandas]". Without them the package imports and records normally, and their serializers are simply not registered.

Setup: where records go¶

The code under test reads its store from the REGRESSION_RECORDS_STORE environment variable when it is imported, so the variable is set first (record_func : recording a first call says why).

import os
import tempfile
from pathlib import Path

# In a project: REGRESSION_RECORDS_STORE=tests/regression_data in a .env file, loaded
# with python-dotenv's load_dotenv(). Here: a fresh temporary directory, empty each run.
STORE = Path(tempfile.mkdtemp(prefix="regression-records-"))
os.environ["REGRESSION_RECORDS_STORE"] = str(STORE)
print("store:", STORE)

Setup: the code under test¶

Replay imports a recorded function by module and name, so the code under test lives in a module, frames, imported from regression_records._examples - support code that ships with the package so that a page can import real code rather than define it in a cell (record_func : recording a first call says more). In your project, this is your own package. Each part is printed where the page first uses it.

Each function exists in a polars and a pandas version. book_data quotes a bid and an ask around each mid price; TICK, when set, rounds every quote to that tick, the change this page replays against later.

import inspect

Recording is off unless switched on; this page switches it on for the whole script. show_output prints what a record holds for a function’s return value.

def show_output(recorded, keys: tuple[str, ...] = ("output",)) -> None:
    """Print ``keys`` of the first record of the ``recorded`` function."""
    records = STORE.joinpath(*recorded.identity.path_parts, "records")
    path = next(records.glob("rec-*.json"))
    record = json.loads(path.read_text())
    print(json.dumps({k: record[k] for k in keys}, indent=2))


enable()

Recording a frame¶

A frame is written as parquet - dtypes intact, compressed, content-addressed - and the record holds a reference plus its shape. First polars, on a book that book_data builds:

print(inspect.getsource(frames.book_data))
print(inspect.getsource(frames.polars_book))

def book_data(n: int) -> dict[str, list | np.ndarray]:
    """Return ``n`` rows of symbols, quotes and volumes as columns."""
    mid, spread = np.array(MIDS[:n]), np.array(SPREADS[:n])
    bid, ask = mid - spread / 2, mid + spread / 2
    if TICK is not None:
        bid, ask = np.round(bid / TICK) * TICK, np.round(ask / TICK) * TICK
    return {
        "symbol": [f"S{i:02d}" for i in range(n)],
        "bid": bid,
        "ask": ask,
        "mid": (bid + ask) / 2,
        "volume": np.arange(1, n + 1) * 100,
    }

@record_func(STORE)
def polars_book(n: int) -> pl.DataFrame:
    """Return a book of ``n`` rows as a polars frame."""
    return pl.DataFrame(book_data(n))

Series¶

A Series records as a one-column parquet file that keeps its name, and compares like a column: name and dtype, then length (in pandas, the index), then values. An unnamed polars series is named ""; an unnamed pandas one has no name at all, which parquet cannot represent, so the record carries it separately.

print(inspect.getsource(frames.polars_returns))
print(inspect.getsource(frames.pandas_rolling))

@record_func(STORE)
def polars_returns(prices: pl.Series) -> pl.Series:
    """Return the simple period returns of ``prices``, named ``"return"``."""
    return prices.pct_change().alias("return")

@record_func(STORE)
def pandas_rolling(values: list[float]) -> pd.Series:
    """Return the two-day rolling mean of ``values``, indexed by calendar day."""
    series = pd.Series(values, index=pd.date_range("2024-01-01", periods=len(values)))
    return series.rolling(2).mean()

print(frames.polars_returns(pl.Series("price", [100.0, 101.0, 99.0])))
print(frames.pandas_rolling([1.0, 2.0, 3.0, 4.0]))

Replaying them¶

Every record replays: the frame and series arguments load back from parquet, the functions run on them, and the results compare equal to the recorded ones.

Column-level diffs¶

Now the change: quotes rounded to a quarter tick. Recording goes off first, so that calling the changed code below, to plot it, records nothing new. With TICK set, the two book functions differ on replay, and a dataframe comparison reports per column, using the ['name'] step in the path grammar, and names the rows that differ rather than printing two frames at you. volume and symbol did not change, so they are not mentioned.

disable()
frames.TICK = 0.25
try:
    current = frames.polars_book(12)
    report = replay(STORE)
finally:
    frames.TICK = None

Which cells moved¶

The report names columns and rows; laid out as the frame, that is a map of the cells the change touched. Rows whose quotes were already on the tick did not move, the mid of a row whose bid and ask moved in opposite directions did not either, and volume never moved at all - each exactly as the report says.

import re

import matplotlib.pyplot as plt
import numpy as np
from matplotlib.colors import LinearSegmentedColormap

    for d in polars_case.comparison.diffs

touched = ~np.isclose(change, 0.0, rtol=0.0, atol=1e-12)

Schema first¶

A schema difference short-circuits the value comparison. Once the columns or their dtypes have changed, per-row differences are noise - the frame is a different frame, and reporting a thousand “row differs” lines would bury the one fact that matters.

before = {"a": [1, 2], "b": [3.0, 4.0]}
after = {"a": [1.0, 2.0], "c": [3.0, 4.0]}
for frame in (pl.DataFrame, pd.DataFrame):
    print(f"\n{frame.__module__.split('.')[0]}:")
    print(compare(frame(before), frame(after)).summary())

Column order is part of the schema, in both libraries, and strict_dtype=False does not relax it: that setting is about dtypes, and a frame whose columns moved is a different frame to anything that reads it by position.

Tolerance on one column¶

path_overrides keys use the same paths the diffs report, so a column that legitimately drifts can be loosened while its neighbours stay strict. Identically for both.

expected = {"price": [10.0, 20.0], "qty": [1.0, 2.0]}
actual = {"price": [10.02, 20.03], "qty": [1.0, 2.000001]}
loose_on_price = ToleranceConfig(
    rtol=1e-7, path_overrides={"$.output['price']": ToleranceConfig(rtol=1e-2)}

for frame in (pl.DataFrame, pd.DataFrame):

Missing values¶

Here the libraries genuinely differ. polars has two things where pandas has one: a null is a missing value and a NaN is a floating-point number. A column that changes from one to the other has changed - mean() skips a null and is poisoned by a NaN - so it is reported, whatever equal_nan says.

null_vs_nan = compare(pl.DataFrame({"x": [1.0, None]}), pl.DataFrame({"x": [1.0, NAN]}))
print(null_vs_nan.summary())
assert not null_vs_nan.passed

comparison failed with 1 diff(s):
  at "$['x']" (value_mismatch): 1 of 2 value(s) are null on one side only at row(s): 1

equal_nan governs NaN against NaN, and nulls in the same place are always equal. Where each side is null is compared first, and the other rows in the column’s own dtype - so an integer column with a null in it is still compared as integers, and identifiers too large for a float are told apart.

nan_frame = pl.DataFrame({"x": [1.0, NAN, None]})
assert compare(nan_frame, nan_frame.clone()).passed, "NaN equals NaN by default"
assert not compare(
    nan_frame, nan_frame.clone(), ToleranceConfig(equal_nan=False)
).passed
print(
    "2**60 + 1 vs 2**60:       ",
    compare(
        pl.DataFrame({"id": [2**60 + 1, None]}), pl.DataFrame({"id": [2**60, None]})
    ).passed,
)

2**60 + 1 vs 2**60:        False

A pandas float column has only NaN, so None and NaN are the same value by the time there is a frame to compare, and equal_nan decides whether two of them match:

pandas_missing = pd.DataFrame({"x": [1.0, None]})
assert compare(pandas_missing, pd.DataFrame({"x": [1.0, NAN]})).passed, "None vs NaN"

Nested columns¶

polars columns can hold lists, arrays and structs. Tolerance reaches inside them: list lengths must match row by row, float and integer leaves compare within the column’s tolerance, and every other leaf exactly. Differences are reported by row.

curves = pl.DataFrame(
    {
        "tenors": [[0.5, 1.0, 2.0], [1.0]],
        "quote": [{"mid": 101.25, "source": "A"}, {"mid": 99.5, "source": "B"}],
    }
)
noise = curves.with_columns(pl.col("tenors").list.eval(pl.element() + 1e-13))
assert compare(curves, noise).passed, "float noise inside a list is within tolerance"

moved = curves.with_columns(
    pl.col("quote").struct.with_fields(pl.field("mid") + pl.Series([0.0, 0.25]))
)
nested = compare(curves, moved)
print(nested.summary())
assert not nested.passed

comparison failed with 1 diff(s):
  at "$['quote']" (value_mismatch): 1 of 2 nested value(s) differ beyond tolerance at row(s): 1

Wide frames¶

Reporting is capped: once enough columns have differed, the rest are replaced by a single summary line. A frame where every column shifted should say so once, not once per column.

for frame in (pl.DataFrame, pd.DataFrame):
    result = compare(
        frame({f"c{i}": [0.0] for i in range(40)}),
        frame({f"c{i}": [1.0] for i in range(40)}),
    )
    print(f"{len(result.diffs)} diff(s) for 40 differing columns")
    print(result.diffs[-1].message)

What is refused¶

Each of these raises SerializationError when recording, rather than writing a record that lost something or could never be read back.

  • A polars LazyFrame is not auto-collected. Collection can be expensive or side-effecting, so calling .collect() stays your decision, made where you can see the cost.

  • A polars Object column is the one polars dtype parquet cannot hold.

  • A pandas object column of mixed types is something Arrow cannot represent.

from regression_records.serialization import (
    SerializationContext,
    default_registry,

Opting in to pickle¶

pandas, and only pandas, has a way out. Unpickling runs code, and a store is committed and shared, so a pickle is never written or read unless you asked for that: build the pandas serializers with allow_pickle=True and swap them into a copy of the default registry. The fallback then applies to that one file, with a warning, because a pickled record is less portable and not inspectable. polars has no such option: every dtype but Object has a parquet form, so there is always a cast that makes the frame recordable.

from regression_records.serialization.pandas_serializer import (
    PandasDataFrameSerializer,
)

pickling = default_registry.copy()
pickling.register(PandasDataFrameSerializer(allow_pickle=True), replace=True)
ctx = SerializationContext(data_dir=Path(tempfile.mkdtemp()), registry=pickling)

with warnings.catch_warnings(record=True) as caught:
    warnings.simplefilter("always")
    tree = to_json_tree(awkward, ctx)

print("stored as:", tree["format"])
assert tree["format"] == "pickle"
for w in caught:
    print(f"{w.category.__name__}: {str(w.message)[:110]}...")

Three things to know about frames on disk¶

  • Parquet is content-addressed, so a frame recorded identically by ten different functions is one file per identity directory - and re-recording an unchanged frame writes nothing.

  • A frame argument’s input hash comes from its parquet bytes. Those are stable from run to run, but not across every polars or pyarrow release. Replay never looks a record up by that hash - it loads the recorded frame and calls the function on it - so an encoding change does not stop old records replaying. It only means a new recording of the same call is filed beside the old one rather than with it.

  • DatetimeIndex.freq does not survive parquet. An index round-trips with its values and dtype but not its inferred frequency. If freq is part of what you are testing, assert on it separately.
