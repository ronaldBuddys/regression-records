Comparison¶

compare() answers one question - how does this value differ from the one that was recorded - and answers it completely.

from regression_records import compare

result = compare(expected, actual)
if not result:
    print(result.summary())

Two properties shape everything below:

  • It collects every difference, never short-circuiting on the first. A run that changed four columns should tell you about four columns, not send you round the loop four times. (Comparisons that would be noise after an earlier finding do stop - see Short-circuiting.)

  • It never raises for a mismatch. compare() is a pure function. Turning a failed comparison into a failed case is replay’s job, which is what keeps the comparison logic independent of recording and replaying.

ComparisonResult¶

Field / method

Meaning

passed: bool

True when no diffs were found.

diffs: list[Diff]

Every difference found, in traversal order.

__bool__()

Truthy iff passed, so if not result: reads naturally.

summary(max_diffs=20) -> str

A multi-line human summary; what a failed ReplayCase lists.

Replay attaches one to each case it could run, as ReplayCase.comparison.

Diff¶

Field

Meaning

path: str

Where the difference is - see Paths.

kind: str

What kind of difference - see below.

expected: str

A short repr of the recorded value.

actual: str

A short repr of the fresh value.

message: str

A sentence describing the difference.

tolerance_used: ToleranceInfo | None

Set when a numeric tolerance decided the outcome.

expected and actual are reprs, truncated to 200 characters - never the live objects. A Diff outlives the comparison inside a ReplayReport, and must not pin a 1GB array in memory to describe a difference in one of its cells.

Diff kinds¶

Kind

Meaning

type_mismatch

The two sides are different types (list vs tuple, array vs scalar).

value_mismatch

Same type, different value - beyond tolerance where tolerance applies.

shape_mismatch

Two arrays of different shape.

dtype_mismatch

Two arrays or numpy scalars of different dtype.

missing_key

Present in the recorded value, absent from the fresh one. Also used for set members.

extra_key

Present in the fresh value, absent from the recorded one.

length_mismatch

Sequences of different length, or dataframes of different height.

schema_mismatch

Dataframe columns, their dtypes, or their order differ.

exception_mismatch

One side raised where the other did not, or raised a different type.

ToleranceInfo¶

Attached to a numeric Diff so the report says what the value was measured against: rtol, atol, and max_abs_diff - the largest finite absolute difference among the mismatched elements (a modulus, for complex values), or None when it isn’t measurable (infinities).

Paths¶

Every Diff carries a path naming exactly where it is. The grammar lives in regression_records.comparison.paths and is public - ToleranceConfig.path_overrides keys are matched against it.

Form

Means

$

The value being compared.

$.output

A recorded call’s return value.

$.state_before

A method receiver’s state before the call.

$.state_after

… and after it.

$.key

A dict entry, or an object attribute.

$[0]

A list or tuple element, by position.

$['price']

A dataframe column.

They nest, so a real path reads like the access that would reach the value: $.state_after.frame['price'], or $.output.rows[3].weights.

The three roots exist so one record’s diffs stay distinguishable, and so each part can be targeted by its own tolerance override.

Tolerance¶

from regression_records import ToleranceConfig

ToleranceConfig(
    rtol=1e-7,  # relative tolerance
    atol=0.0,  # absolute tolerance
    equal_nan=True,  # NaN in the same position on both sides is equal
    strict_dtype=True,  # a dtype change is a failure
    path_overrides={},  # per-subtree overrides
)

A config is passed to replay() or replay_tests() as tolerance, and per function through tolerance_overrides (see Replay). Recording takes none: it stores values exactly.

Two numbers are close when abs(actual - expected) <= atol + rtol * abs(expected) - numpy.isclose semantics.

Infinities compare exactly: inf matches inf and nothing else, regardless of rtol. NaN is governed by equal_nan, which defaults to True because a recorded NaN is usually a meaningful “no value here” rather than an error. The same goes for other values that are not equal to themselves - Decimal("NaN"), a complex with a NaN part, pandas.NaT: under equal_nan two of the same type match when their repr does, so a complex’s other part still has to agree. NaT in numpy datetime64 and timedelta64 arrays and scalars matches NaT in the same way, at the same position; a NaT against a date is still a difference.

bool is deliberately excluded from numeric comparison despite subclassing int: True is not “1, within tolerance” - it is a different kind of answer. The same holds for a boolean pandas column, though pandas itself counts one as numeric.

Integers are compared exactly, whatever the tolerance - scalars, numpy integer arrays, and integer pandas (nullable Int64 included) and polars columns alike. They are counts and identifiers, not measurements: a row count of 1,000,000,050 is not 1,000,000,000 “within tolerance”. Tolerance applies once a float is involved, so an integer recorded where a float is now computed is compared within tolerance - unless it is beyond 2**53, which no float can represent exactly.

Why a dtype change is a failure¶

strict_dtype=True is the default, so float64 becoming float32 is reported even when every value still agrees to within rtol.

The values agreeing today is not the point. A dtype change is a change in what the code promises: different precision, a different overflow point, and different behavior on inputs your recorded case does not happen to cover. It is a thing you want to have chosen rather than to have drifted into. Set strict_dtype=False when you have chosen it; it relaxes arrays, numpy scalars, Series and dataframe schemas alike (a dataframe’s columns must still have the same names, in the same order).

path_overrides¶

Tolerance is often not uniform. A price column may need to be exact while a Monte-Carlo estimate needs 1%:

ToleranceConfig(
    rtol=0.0,
    path_overrides={
        "$.output['estimate']": ToleranceConfig(rtol=1e-2),
        "$.state_after": ToleranceConfig(rtol=1e-9),
    },
)

An override applies to its path and everything beneath it. When several match, the most specific - the longest - prefix wins, so a broad override on $.output can be narrowed for one column beneath it.

An override changes only the fields you pass to it; every other field is inherited from the config in effect above it - the root config’s, or a shorter override’s that also matches. Under a root config with atol=1e-6, the ToleranceConfig(rtol=1e-2) override above compares the estimate with rtol=1e-2 and atol=1e-6. Passing a field counts even when the value equals the default: ToleranceConfig(atol=0.0) under a parent with atol=1e-3 takes the absolute tolerance back to zero for its subtree. path_overrides combine the same way: an override may carry overrides of its own, and the ones it does not name still come from the configs above it.

ToleranceConfig is frozen, because one config is shared by every case of a replay. Derive a variant with dataclasses.replace(config, rtol=...). replace passes every field, so a config derived with it counts all of them as set: as an override it inherits nothing. Build overrides with the constructor.

Note that overrides are matched against the reported path, so they are only as stable as your data’s shape. A key rename changes the path.

What gets compared how¶

The walker handles containers itself and delegates “inconvenient” leaves to a Comparator, mirroring how serialization dispatches to its serializer registry.

Dicts are compared key by key, reporting missing_key and extra_key for each difference in the key sets - both directions, so you see what appeared as well as what vanished.

Lists and tuples are compared elementwise by position, and are not interchangeable: a function that started returning a list where it used to return a tuple has changed its contract. A named tuple is not a sequence here: it is compared as an object, field by field, so a diff names the field ($.output.ask, not $.output[1]), and it matches only the same named tuple class. Any other list or tuple subclass is recorded as the builtin, and compares as one.

A MappingProxyType is compared key by key like a dict, but is its own kind: a function that returned a read-only view and now returns a dict has changed.

Sets are compared by membership. There is no stable position to pair members up by, so tolerance cannot meaningfully apply.

Numpy arrays check shape, then dtype, then values - numerically with tolerance for numeric dtypes, exactly otherwise. A shape mismatch stops there; so does a dtype mismatch between incomparable kinds (float vs str), where an elementwise comparison would be meaningless.

Numpy scalars keep their dtype through recording, so float32 vs float64 is a dtype_mismatch. When only one side is a numpy scalar - recorded as np.float64, recomputed as a plain float - there are not two dtypes to compare and the values are simply checked numerically.

Dataframes (polars and pandas) compare schema, then height, then column by column. Integer and float columns use tolerance; others, Decimal included, compare exactly.

In a polars column a null is missing and a NaN is a number, and the comparison keeps them apart: where each side is null is compared first, and a row that is null on one side only is reported as such, whatever equal_nan says. That setting governs NaN against NaN. The remaining rows are then compared in the column’s own dtype, so an integer column with nulls stays integer, and integers beyond 2**53 are compared exactly (in a numpy array too) because no float can tell them apart. pandas has one missing value per dtype, so there equal_nan still decides whether two missing values match.

A pandas object column and a str column count as the same dtype. Parquet stores both as strings, and reads them back as whichever the loading pandas uses by default (object up to pandas 2, str from pandas 3), so otherwise a record would fail on a dtype it never had a say in - under one pandas version or across two. Their values are still compared. The opt-in "string" dtype, missing as pd.NA, stays distinct.

Tolerance reaches inside a nested polars column too. A List, Array or Struct that holds floats is walked down to its leaves: list lengths must match row by row, numeric leaves compare within the column’s tolerance, and every other leaf exactly. It is reported by row, as one diff per column; a path_overrides entry names the column, not a field inside it.

Series (polars and pandas) compare name and dtype, then length (for pandas, the index), then values exactly as a dataframe column would.

Objects are compared attribute by attribute - their __dict__ plus every set slot, the same attributes a record stores - never through __eq__ or __getstate__. Each attribute goes back through the top-level walker, so a nested array or dataframe is compared by its comparator, with the right path and tolerance. Two objects of different classes are a type_mismatch before any attribute is examined. A value with no attributes to walk (a C type no comparator claims) is compared by plain equality.

Exceptions compare on exc_type only: the module-qualified class name, so the builtin ConnectionError and requests.exceptions.ConnectionError differ. A schema version 1 record holds the bare class name, and is compared by bare name. Messages routinely carry nondeterministic detail - addresses, paths, timings - so a changed message is not a regression, while a changed type is. An exception on one side and a value on the other is always a failing exception_mismatch.

Short-circuiting¶

The rule is: stop when continuing would produce noise rather than signal.

After

Skipped

Because

A sequence length mismatch

Elementwise comparison

Positions no longer line up; every element after an insertion would be reported as changed.

A dataframe schema mismatch

Height and values

The columns being compared aren’t the same columns.

A dataframe height mismatch

Column values

As above, for rows.

An array shape mismatch

Values

There is nothing to line up.

An object type mismatch

Attributes

Different classes; matching attribute names would be coincidence.

Everything else keeps going and collects.

Diff caps¶

Two caps keep a report readable when something changed globally.

Within a column or array, at most 20 positions are listed. The message always states the true count: "312 of 1000 element(s) differ beyond tolerance at index/indices: 0, 1, 2, ... (309 more)".

Across columns, once more than 20 columns have differed, the per-column diffs already collected for the remainder are dropped and replaced by one summary diff. A frame where every column shifted should say so once, not four hundred times.

Both default to 20 and are constructor arguments on the array and dataframe comparators, for a registry you build yourself.

ComparisonResult.summary() applies its own separate cap of 20 lines to whatever it is given; result.diffs always holds everything.

Writing a comparator¶

A Comparator gives your own type useful diffs instead of plain equality:

from regression_records import register_comparator
from regression_records.comparison.base import Diff


class TimeSeriesComparator:
    def can_handle(self, expected, actual):
        # Called with either side matching - the fresh value may be something else
        # entirely, which is itself the difference worth reporting.
        return isinstance(expected, TimeSeries) or isinstance(actual, TimeSeries)

    def compare(self, expected, actual, path, tolerance, compare_fn, diffs):
        if expected.freq != actual.freq:
            diffs.append(
                Diff(
                    path=path,
                    kind="schema_mismatch",
                    expected=str(expected.freq),
                    actual=str(actual.freq),
                    message=f"frequency {actual.freq} != expected {expected.freq}",
                )
            )
            return
        compare_fn(expected.values, actual.values, path)  # recurse for the array


register_comparator(TimeSeriesComparator())

Three things to know:

  • can_handle is asked about both sides and dispatches if either matches. Handling “only one side is my type” is part of the job; comparison.base.require_both does it for you.

  • Append to diffs; do not return anything. compare_fn(expected, actual, path) recurses into the top-level walker and appends to the same list, so a comparator that both reports its own findings and recurses cannot double-count them.

  • tolerance arrives already resolved for this path, with any override applied.

register_comparator places it behind the built-in comparators; the registry is consulted before containers and objects are walked, so a comparator also wins for any class it claims. priority= takes an explicit position (0 is consulted first); one outside the list is refused with ValueError. Register on a ComparatorRegistry.copy() and pass it as replay(..., comparator_registry=...) instead when the change should be scoped to one replay rather than global.
